# 一、项目背景与理论学习
校园卡、钥匙、雨伞和耳机等物品丢失后，同学们通常在班级群、宿舍群或朋友圈发布消息。这些信息分散、容易被新消息覆盖，失主和拾物者也可能不在同一个群聊中。为解决这一问题，我们设计了“校园失物招领小程序”，集中展示寻物和招领信息。
阅读《构建之法》第3章和第8章后，我们认识到结对合作需要共同讨论和相互复核；需求分析应从真实用户和使用场景出发；原型设计则要保证流程简单、页面清晰，并考虑后续代码实现的可行性。



# 二、用户需求与主要功能

主要用户包括丢失物品的学生、捡到物品的学生和提供线索的普通浏览者。他们需要集中浏览信息、快速搜索物品、查看时间地点和特征、发布寻物或招领信息，并在物品找回后更新状态。

主要功能如下：

1. 浏览并区分寻物、招领信息。
2. 按关键词搜索和筛选物品。
3. 查看物品图片、特征、时间、地点、状态及发布者信息。
4. 发布寻物信息或招领信息。
5. 联系发布者，查看或提交评论与线索。
6. 收藏信息，并在“我的收藏”中查看。
7. 查看个人发布并修改为“已找回”或“已归还”。

# 四、基本流程

# 五、合作过程

我们先共同分析题目并确定核心页面，再由一人初步整理需求和流程，另一人初步制作界面与交互，之后共同讨论修改需求和共同制作figma原型。制作过程中，我们多次调整图层、自动布局和按钮位置，并测试每条Prototype连线。结对复核帮助我们及时发现页面遗漏和跳转目标错误，也避免加入过多难以实现的功能。
